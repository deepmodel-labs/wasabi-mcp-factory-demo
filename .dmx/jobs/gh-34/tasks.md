## Phase 1: Transport-error handling in rest.py
- [x] Add `_transport_error(operation: str, url: str | httpx.URL, exc: httpx.TransportError) -> ToolRefused` to `src/wasabi_mcp/rest.py`. It classifies DNS (`socket.gaierror` in the `__cause__`/`__context__` chain, or message substrings "Name or service not known" / "nodename nor servname" / "getaddrinfo" / "Temporary failure in name resolution") → `couldn't resolve host {host}`, code `DNSError`. `TimeoutException` → `timed out {connecting to|reading from|writing to|waiting for a connection to} {host}`, code `Timeout`. `ConnectError` → `couldn't connect to {host}` plus `(connection refused|reset|unreachable)` when detectable, code `NetworkError`. `ReadError`/`WriteError`/`RemoteProtocolError` → `the connection to {host} was reset or closed`, code `NetworkError`. Any other `TransportError` → `network error talking to {host}`, code `NetworkError`. The message is `"{operation} failed: {reason}"` and is built only from the operation, `httpx.URL(url).host` and the classified reason, never from `str(exc)`.
- [x] Give `_send` an `operation` parameter and wrap `client.send(...)` in `except httpx.TransportError as exc: raise _transport_error(operation, url, exc) from exc`.
- [x] Pass `action` from `signed_s3` and `action_name` from `iam_query` into `_send`.
- [x] Wrap the `client.get(...)` in `stats_get` the same way, with operation `Stats API GET {path}` and URL `settings.stats_url + path`.
- [x] Wrap the `client.request(...)` in `wacm_request` the same way, with operation `WACM Connect {METHOD} {path}` and URL `settings.wacm_url + path`.
- [x] Confirm that only `httpx.TransportError` is caught, so `ToolRefused` from credential checks and region lookup, and the existing 4xx/5xx `ToolRefused` messages, pass through unchanged. Tool modules that catch `ToolRefused` (`_wacm.call`, `bucket_ops`, `compliance`, `objects_ext` NoSuchKey fallback, `stats._get`) re-raise non-matching errors unchanged, so no tool edits are needed.
